# Benchmark Table Generation Scripts

This directory contains various Python scripts to generate figures and tables of
results by compiling the benchmark code, running benchmarks, and parsing their
outputs.

## Overview

- **`generate_raw_outputs.py`**: Compiles the benchmark with specified compiler(s) and runs multiple configurations, saving raw outputs
- **`generate_variant_comparison_table.py`**: Parses raw outputs and generates LaTeX table comparing homogeneous vs heterogeneous variants
- **`generate_algorithm_comparison_table.py`**: Parses raw outputs and generates LaTeX table comparing all integer-to-string algorithms
- **`utils.py`**: Shared utility functions used by all scripts

## Prerequisites

Python 3.8+ installed

## Usage

**Important**: All scripts should be run from the project root directory, not from within the `scripts/` folder.

```bash
cd /path/to/float_string_chars-gen_bench
./scripts/generate_raw_outputs.py [compiler]
```

### Step 1: Generate Raw Benchmark Data

Run the benchmark program for all configurations with a specific compiler:

```bash
# Using g++ (default)
./scripts/generate_raw_outputs.py g++

# Using clang++
./scripts/generate_raw_outputs.py clang++

# Using both compilers
./scripts/generate_raw_outputs.py all
```

**Command-line options:**

```bash
./scripts/generate_raw_outputs.py [compiler] [OPTIONS]

Positional arguments:
  compiler              Compiler to use: g++, clang++, or 'all' for both (default: g++)

Optional arguments:
  --build-dir DIR       Build directory (default: build)
  --output-dir DIR      Output directory for raw files (default: ./outputs)
  --clean               Clean build directory before compilation
  --skip-compile        Skip compilation (use existing build)
  --timeout SECONDS     Timeout per benchmark run (default: 600)
  --table               Generate only datasets needed for algorithm comparison table
  --figure              Generate only datasets needed for digit-length figure
```

**Examples:**

```bash
# Clean build with g++ and save to custom output directory
./scripts/generate_raw_outputs.py g++ --clean --output-dir my_results

# Use existing build, run with clang++
./scripts/generate_raw_outputs.py clang++ --skip-compile

# Run with both compilers
./scripts/generate_raw_outputs.py all

# Generate only table datasets (faster, ~5-10 datasets)
./scripts/generate_raw_outputs.py g++ --table

# Generate only figure datasets (slower, 20 digit-length datasets)
./scripts/generate_raw_outputs.py g++ --figure

# Generate both (default if no flags specified)
./scripts/generate_raw_outputs.py g++
```

**Selective data generation:**

The `--table` and `--figure` flags allow you to generate only the data needed
for specific outputs:

- **`--table`**: Generates only the 5 datasets needed for the **variant comparison table** (homogeneous vs heterogeneous: 4 real-world + natural-8)
- **`--figure`**: Generates all 20 uniform-Ndigit-1M datasets needed for the digit-length figure (N=1 to 20)
- **No flags**: Generates all datasets (default, backward compatible)

**Note**: The algorithm comparison table uses a subset of the data generated by
`--table`, but requires running benchmarks with all algorithms enabled
(default). The `--table` flag only controls which *datasets* are benchmarked,
not which algorithms.

The script automatically skips regenerating files that already exist in the
outputs directory, so you can safely run:
```bash
./scripts/generate_raw_outputs.py g++ --table   # Generate table data first
./scripts/generate_raw_outputs.py g++ --figure  # Then figure data (won't regenerate table data)
```

This will:
- Compile the benchmark code with the specified compiler(s)
- Run benchmarks for homogeneous and heterogeneous variants
- Test real-world datasets (CITM catalog, Twitter JSON, StackOverflow timestamps, US patents)
- Test synthetic datasets (20 uniform digit-length distributions 1-20, natural-8, natural-16, uniform-1to20) with 1M integers each
- Save raw outputs to `outputs/*.raw` files
- Skip regenerating files that already exist (safe to run multiple times)

**Note**: This step takes significant time (potentially 30-60 minutes per
compiler without flags, or 90+ minutes with --figure due to 20 digit-length
datasets) since it runs many benchmark iterations for statistical accuracy.

Output files are named like:
- `outputs/Intel_R__Core_TM__i7-9700K_CPU_3.60GHz_g++_uniform-1M-homo.raw`
- `outputs/Intel_R__Core_TM__i7-9700K_CPU_3.60GHz_clang++_uniform-1M-hetero.raw`
- etc.

The filename includes: CPU model, compiler, dataset name, and variant.

### Step 2: Generate LaTeX Tables

#### Variant Comparison Table (Homogeneous vs Heterogeneous)

Parse the raw outputs and create a table comparing the two AVX-512 variants:

```bash
./scripts/generate_variant_comparison_table.py
```

**Command-line options:**

```bash
./scripts/generate_variant_comparison_table.py [OPTIONS]

Optional arguments:
  --compiler COMPILER   Compiler to use for finding output files (default: g++)
  --input-dir DIR       Directory containing raw benchmark files (default: ./outputs)
  --output-file FILE    Output LaTeX file name (default: table_homogeneous_vs_heterogeneous.tex)
```

**Examples:**

```bash
# Generate table from g++ results (default)
./scripts/generate_variant_comparison_table.py

# Generate table from clang++ results
./scripts/generate_variant_comparison_table.py --compiler clang++

# Read from custom directory
./scripts/generate_variant_comparison_table.py --input-dir my_results

# Custom output file name
./scripts/generate_variant_comparison_table.py --output-file my_variant_table.tex
```

This will:
- Parse all `outputs/*.raw` files for the specified compiler
- Extract timing information (ns/d - nanoseconds per digit/character)
- Determine which variant was auto-selected for each dataset
- Generate a LaTeX table file
- Print a preview of the table

#### Algorithm Comparison Table (All Algorithms)

Generate a comprehensive table comparing all integer-to-string algorithms:

```bash
./scripts/generate_algorithm_comparison_table.py
```

**Command-line options:**

```bash
./scripts/generate_algorithm_comparison_table.py [OPTIONS]

Optional arguments:
  --compiler COMPILER   Compiler to use for finding output files (default: g++)
  --input-dir DIR       Directory containing raw benchmark files (default: ./outputs)
  --output-file FILE    Output LaTeX file name (default: table_algorithm_comparison.tex)
```

**Examples:**

```bash
# Generate algorithm comparison table from g++ results (default)
./scripts/generate_algorithm_comparison_table.py

# Generate from clang++ results
./scripts/generate_algorithm_comparison_table.py --compiler clang++

# Read from custom directory
./scripts/generate_algorithm_comparison_table.py --input-dir my_results
```

This will:
- Parse benchmark outputs for all algorithms
- Extract multiple metrics: ns/d (nanoseconds per character), i/d (instructions per character), c/d (cycles per character)
- Calculate speedup percentages relative to AVX-512 for each metric
- Compare 10 different algorithms across 5 real-world and synthetic datasets
- Bold the best (lowest) value for each metric
- Generate a comprehensive LaTeX table (uses `table` for single-column width)

#### Digit-Length Comparison Figure

Generate a figure comparing algorithm performance across different digit lengths:

```bash
./scripts/generate_digit_length_figure.py [compiler] [cpu_model]
```

**Arguments:**
- `compiler`: Compiler used for benchmarks (g++ or clang++, default: g++)
- `cpu_model`: Optional CPU model prefix in filenames (auto-detected if not provided)

**Examples:**

```bash
# Generate figure from g++ results (auto-detects CPU model)
./scripts/generate_digit_length_figure.py g++

# Explicitly specify CPU model prefix
./scripts/generate_digit_length_figure.py g++ "AMD_Ryzen_9_9900X_12-Core_Processor"

# Generate from clang++ results
./scripts/generate_digit_length_figure.py clang++
```

This will:
- Auto-detect CPU model from existing .raw files if not specified
- Parse benchmark outputs for uniform-Ndigit-1M datasets (N=1 to 20)
- Extract ns/d metrics for all algorithms
- Generate a line plot showing performance vs digit length
- Save as PDF in the outputs directory
